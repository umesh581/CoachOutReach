# Outreach Engine

Finds coaches and consultants in the US, UK, and Australia who already have an
offer and are likely ready to invest in sales funnels, Meta Ads, or AI
automation; analyzes their current funnel; drafts personalized cold outreach;
and tracks the whole relationship in a built-in CRM.

## Stack

- **Frontend**: Next.js 14 (App Router), TypeScript, Tailwind CSS
- **Database + auth**: Supabase (Postgres + Row Level Security + Auth)
- **Web scraping**: Firecrawl (`/scrape`)
- **AI generation**: Anthropic API (Claude) for findings briefs + outreach copy
- **Email**: Resend, with a webhook for opens/clicks/bounces/complaints
- **Orchestration** (optional): n8n can call this app's REST API
  (`/api/prospects/import`, `/api/prospects/[id]/analyze`,
  `/api/prospects/[id]/generate-message`) on a schedule for sourcing and
  enrichment jobs. The app itself only performs on-demand actions triggered
  from the UI — no built-in cron.

## Getting started

1. **Create a Supabase project** and run the migration:

   ```bash
   # via the Supabase SQL editor, paste the contents of:
   supabase/migrations/0001_init.sql
   ```

   This creates `campaigns`, `prospects`, `funnel_analyses`, `messages`,
   `activities`, and `settings` tables, all with Row Level Security enabled
   and owner-scoped policies (`owner_id = auth.uid()`).

2. **Copy environment variables**:

   ```bash
   cp .env.example .env.local
   ```

   Fill in `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, and
   `SUPABASE_SERVICE_ROLE_KEY` from your Supabase project settings. Generate
   `UNSUBSCRIBE_SECRET` with `openssl rand -hex 32`.

3. **Install and run**:

   ```bash
   npm install
   npm run dev
   ```

4. Visit `/login`, click **Create account** to register the single owner
   account (the first account created owns all data — this is a single-user
   MVP, not multi-tenant).

5. Go to **Settings** and configure:
   - Sender name, company, and **physical mailing address** (required by
     CAN-SPAM and expected in the UK/AU on every commercial email)
   - Sender email (must be a verified sender/domain in Resend)
   - Daily send limit (defaults to 40 — keep this low while warming up a new
     sending domain)
   - Firecrawl, Anthropic, and Resend API keys (stored server-side only,
     never sent to the browser; env vars in `.env.local` act as a fallback)

6. **Import prospects** via CSV (Apollo/Clay/Sales Navigator export) from
   `/prospects/import`, or add them manually from the kanban board.

7. On a prospect's detail page: **Analyze funnel** (Firecrawl + Claude) →
   **Generate message** (Claude, using the findings brief) → review/edit the
   draft → **Send** (Resend). Nothing sends without this manual review step.

8. Configure a Resend webhook pointing at `/api/webhooks/resend` for
   `email.opened`, `email.bounced`, `email.complained`, `email.clicked`, and
   `email.delivered` events, and set `RESEND_WEBHOOK_SECRET` from Resend's
   webhook settings so signatures can be verified.

## Compliance, built in from the start

- Every generated outreach email appends a footer with the real sender
  name/company, a physical mailing address, and a one-click unsubscribe link
  (`src/lib/compliance.ts`).
- The unsubscribe link is HMAC-signed per prospect (`UNSUBSCRIBE_SECRET`) so
  it can't be forged, and posts to a public `/api/unsubscribe` endpoint that
  sets `prospects.stage = 'unsubscribed'`. Every send path checks this stage
  and refuses to send to an unsubscribed prospect.
- A Resend bounce or spam complaint automatically flips the prospect to
  `unsubscribed` too, so a bad send never gets a second attempt.
- Sends are capped by a configurable daily limit (`checkDailySendLimit` in
  `src/lib/resend.ts`) to protect sender reputation while warming up a
  domain.
- Subject lines are generated by Claude with an explicit instruction to
  reflect the actual email content — never clickbait.
- Prospect sourcing is CSV-only (Apollo/Clay/Sales Navigator exports). This
  app never scrapes LinkedIn profile pages directly.

## What's intentionally not built (MVP scope)

- No LinkedIn DM automation
- No auto-send without human review — every message starts as a `draft` and
  requires an explicit edit/approve/send step in the UI
- No multi-tenant support — single owner user, enforced by RLS policies that
  key off `auth.uid()`

## Project layout

```
src/
  app/
    (app)/                 # authenticated shell: dashboard, prospects, campaigns, settings
    api/                   # route handlers (CRUD, analyze, generate-message, send, webhooks)
    login/                 # auth pages + server actions
    unsubscribe/           # public one-click unsubscribe confirmation page
  components/              # client components (kanban board, forms, detail views)
  lib/
    supabase/              # browser / server / admin (service-role) Supabase clients
    anthropic.ts           # Claude prompts: findings brief + outreach message generation
    firecrawl.ts           # Firecrawl /scrape wrapper
    resend.ts              # Resend send + daily rate limit check
    compliance.ts          # unsubscribe token signing + compliance footer
    settings.ts            # merges per-owner DB settings with env var fallbacks
supabase/migrations/       # SQL schema + RLS policies
```
